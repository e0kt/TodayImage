# Contract: daily_records.json 的 resets 字段

**Feature**: `004-group-category-reset`

**不新增文件。** 在既有的 `data/TodayImage/daily_records.json` 上增加一个 `resets` 字段。

## Schema

```json
{
  "version": 1,
  "date": "2026-09-17",
  "records": {
    "949840934|onebot:10000001|黑丝": {
      "image": "/.../黑丝/a.jpg",
      "created_at": 1758000000.0
    }
  },
  "resets": {
    "949840934|黑丝": 2
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `resets` | `object` | `<群>\|<类型>` → 当天被重置的次数 |

## 为什么放在这里而不是单独开一个文件

- **生命周期完全一致**。重置代数只在当天有意义，而 `save_records` 已经实现了「写入时丢弃非当天数据」。
  放一起，FR-406（次日失效）不需要任何新代码。
- **原子性是硬需求**。清记录与递增代数必须一起生效：分两个文件的话，中间崩溃会留下
  「记录清了但种子没变」= 所有人抽回原图 —— 恰好是本功能要解决的那个 bug 的复现。
  同一份文件一次 `os.replace` 即可排除这种中间态。
- 体量极小：一群一类型一个整数。

## Rules

- **S-401** — 键为 `<chat_key>|<category>`，解析只切**第一个**分隔符，故类型名含 `|` 时仍可还原。
- **S-402** — 缺省为 `0`；`resets` 字段缺失等同于空表（老文件可直接读，无需迁移）。
- **S-403** — 写入时若 `date` 非今日，`records` 与 `resets` **一并**丢弃（V-EPO-4、I-405）。
- **S-404** — 与 `records` 同一次原子写：`mkstemp` → `fsync` → `os.replace`。
- **S-405** — 读取失败（文件损坏）时 `resets` 视为空表，与 `records` 的既有降级方式一致 ——
  退化结果是「回到未重置状态」，不会放大影响面。
- **S-406** — 私聊不写 `resets`（I-403）。
- **S-407** — 只增不减，不设上限；整个字段随当天数据每日清零。

## 向后兼容

现存的 `daily_records.json` 没有 `resets` 字段，按 S-402 读作空表，即「所有 (群,类型) 的 epoch 均为 0」，
而 epoch=0 的种子与改动前逐字节一致（V-SEED-1）。**因此升级不需要迁移，也不会改变任何人当天已经拿到的图。**
