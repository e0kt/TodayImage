# Contract: 回复删图命令

**Feature**: `005-reply-delete-image`

在 004 之上新增一条命令。抽图命令的判定顺序不变；本功能只改变**发送方式**
（加 `wait_recall=True`）与**图库内容**。

## 新增 SV

| SV 名 | `pm` | priority | 拥有命令 |
|---|---|---|---|
| `今日图片-删图` | **3** | 21 | `删除<标签>`（需为回复） |

`pm=3` 同时是**默认权限**与**上界**：群管理员及以上可用，普通群友进不来。
另有配置项可把实际阈值**收紧**到 `pm<=1`（仅 master），供图库不可恢复的部署使用。

> handler 内会按配置再判一次 —— 这是本项目第一次在 handler 内自查权限（003 R1 说过要避免）。
> 偏离是有意的：SV 的 `pm` 是注册期常量，无法随配置变化。
> 约束有三条：只**收紧**、永不放宽到 SV 之外；判断集中在一个函数里；由测试钉死。

### 与其它命令的权限对比

| 命令 | 默认权限 | 修复的是什么 |
|---|---|---|
| `TodayImage允许` | `pm<=3` | 本群的可见范围 |
| `TodayImage重置` | `pm<=1` | 本群所有人当天的结果 |
| **`删除<标签>`（本功能）** | **`pm<=3`**（可收紧到 1） | **图库里一张打错标签的图** |

**为什么不按「影响所有群」来收紧**：错标本身就是全局的 —— 一张图被打错标签，
对所有群都是错的；删掉它，所有群都被修复。这不是把局部权限扩大到全局，
而是用一个全局操作修复一个全局错误。按影响面收紧，等于让错误比修复更容易扩散。

`TodayImage重置` 之所以更严，是因为它改变的是**已经正确发出**的结果；
本功能改变的是**本来就错**的数据。

## `删除<标签>`（对一条抽图消息回复）

- **触发**：`on_command(('删除',), block=True)`，且要求 `ev.reply_id` 非空。
- **参数**：标签在 `ev.text`，容忍两侧括号与空白（`删除【黑丝】` ≡ `删除 黑丝` ≡ `删除黑丝`）。
- **使用方式**：**必须是回复**。在群里长按/右键机器人发出的那张图 → 回复 → 输入 `删除黑丝`。

### 解析（三级退让，任何不确定都不删）

1. `reply_id` 命中**回执表** → 唯一确定
2. 未命中 → 该会话该类型当天**恰好一条**记录 → 采用
3. 零条或多条 → 拒绝

### 回复

| 情形 | 回复 |
|---|---|
| 成功 | `已删除【<类型>】的这张图，<N> 人可以重新抽了。` |
| 文件已不在磁盘 | `该图片文件已不存在，已清理 <N> 条记录，相关的人可以重新抽了。` |
| 认不出是哪张（`not_found`） | `认不出这是哪一张。请改用「删除图片 <类型> <图片ID>」，图片ID 可通过「查看图片 <类型>」获取。` |
| 多个候选（`ambiguous`） | `无法确定是哪一张，候选：<ID1>、<ID2>…。请改用「删除图片 <类型> <图片ID>」。` |
| 标签与实际类型不符（`tag_mismatch`） | `这张图属于【<实际类型>】，不是【<你写的>】。为避免误删，未做任何改动。` |
| 不是回复 / 被回复的不是抽图（`not_a_draw`） | `请对机器人发出的那张图**回复**本命令。` |
| 已收紧为仅 master 且发送者是管理员 | `当前配置下只有机器人主人可以删除图库文件。` |
| `pm>3`（普通群友） | *(无回复 —— SV 在 handler 之前拒绝)* |

**五种失败必须彼此不同**（SC-507），且**任何失败都不删除任何文件**（SC-502）。

### 成功后的副作用

| 作用 | 范围 |
|---|---|
| 删除文件 | 本地图库，**全局** |
| 清理当日记录 | **所有**指向该图的记录，跨群、跨用户 |
| 重置代数 +1 | 每个受影响的 `(会话, 类型)` |
| 加入排除集 | 保证重抽不会再碰到它 |
| 失效扫描缓存 | 立即生效，不等 TTL |

### 日志

每次成功删除记一条 `info`：操作者、会话、被删文件、清理记录数、受影响会话数（FR-514）。
这是本插件唯一一个**不可逆**且**全局**的操作。

## 对抽图命令的影响

判定顺序**完全不变**。唯一改动是发送方式：

```text
之前：bot.send(messages)
之后：bot.send(messages, wait_recall=True)  → 拿到消息 ID 记进回执表
```

**必须保证**：拿不到 ID（适配器不支持回执）时**立即放弃**，不重试、不报错、不拖慢后续发送。
核心有熔断（连续超时后 latch 为不支持并立即返回），但实现不得依赖它来"兜住"每一次发送。

拿不到 ID 的后果只是本功能退化为「总是提示改用 `删除图片 <类型> <图片ID>`」。
