# Feature Specification: 回复删图

**Feature Branch**: `005-reply-delete-image`

**Created**: 2026-09-19

**Status**: Draft

**Input**: User description: "admin/master（我）对某张图回复删除<标签> 可以把这张图片从本地图库中删除并且可以允许抽到这张图的人重新抽一次，这样可以避免tag打错之后发错图的情况"

## Overview

打标（wd14）难免出错，错标的图会被分到错误的类型里发出去。现在的补救手段是
`删除图片 <类型> <图片ID>`——需要先 `查看图片` 拿到 8 位 ID，在几千张图的类型里很不现实。

本功能提供一条就地补救的通道：**对机器人发出的那张图回复 `删除<标签>`**，即可

1. 把该图片文件从本地图库里删除，并且
2. 让**当天抽到这张图的人**重新抽一次。

第 2 条是必须的：图删了但记录还钉着它，那些人当天就只能收到静默（图片不存在），
等于把一个错标问题变成了一个"今天没图"问题。

### 无法回避的前提：必须先认出"这张图"

实测（生产日志）：回复事件里适配器**只给** `reply_id` 和被回复消息的**文本**，
`image` / `image_list` / `image_id` **全是空**。也就是说，拿不到被回复的那张图本身。
所以「哪一张」必须靠别的办法解析——这是本功能的核心难点，详见 research R1/R2。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 回复即删并让对方重抽 (Priority: P1)

群里有人抽到一张明显不属于该类型的图。我（master）直接对那条消息回复 `删除黑丝`。
机器人删掉该文件，并让当天抽到它的人可以重新抽。

**Why this priority**: 这就是功能本身。

**Independent Test**: 让一个账号抽一张，记下是哪张；master 回复 `删除<类型>`；
确认文件已从磁盘消失，且该账号再抽能拿到**另一张**。

**Acceptance Scenarios**:

1. **Given** 甲今天抽到了 `黑丝/X.jpg`，**When** master 对那条消息回复 `删除黑丝`，
   **Then** `X.jpg` 从本地图库中被删除，机器人回复确认。
2. **Given** 上一步完成，**When** 甲再发 `今日黑丝`，**Then** 拿到**另一张**图，而不是静默。
3. **Given** 同一张图当天还被乙抽到过，**When** 删除后乙再抽，**Then** 乙也能拿到新图。
4. **Given** 同一张图在**别的群**也被抽到过，**Then** 那些群的人同样可以重抽 ——
   图库是全局的，删除影响所有群。
5. **Given** 删除完成，**When** 之后任何人抽该类型，**Then** 都不可能再抽到这张图。
6. **Given** 标签写错（`删除白丝` 但图其实在 `黑丝`），**Then** 机器人拒绝并说明不匹配，
   **不**删除任何文件。

---

### User Story 2 - 认不出是哪张图时要说清楚 (Priority: P1)

由于适配器不返回被回复的图片，识别可能失败。失败时必须明确告知并给出可行的替代做法，
而不是静默、也不是删错文件。

**Why this priority**: 这是一个**破坏性**操作。识别不确定时删错文件是不可接受的后果，
比功能不可用严重得多。

**Independent Test**: 在无法解析的情形下回复该命令，确认没有任何文件被删除且回复可操作。

**Acceptance Scenarios**:

1. **Given** 无法把这条回复对应到任何一张已发出的图，**When** 执行删除，
   **Then** 不删除任何文件，并告知改用 `删除图片 <类型> <图片ID>`。
2. **Given** 能对应到**多张**候选图（无法唯一确定），**Then** 不删除，并列出候选的图片ID 供选择。
3. **Given** 被回复的消息不是机器人发出的抽图，**Then** 不删除并说明。
4. **Given** 被回复的那张图对应的文件已经不在磁盘上，**Then** 报告该情况，但仍然清理掉
   指向它的当日记录，让人能重抽。
5. **Given** 任何一种失败，**When** 检查磁盘，**Then** 图库文件数**未减少**。

---

### User Story 3 - 权限与留痕 (Priority: P1)

删除作用于全局图库。权限与分群授权同级（群管理员及以上），每次删除都要留痕。

**Why this priority**: 这是一个会改动共用资源的操作，必须能追溯到人；
同时权限不能低到让任意群友都能删。

**Independent Test**: 用普通群友、群管理员、master 各试一次，确认只有被授权的级别能删。

**Acceptance Scenarios**:

1. **Given** 普通群友（`user_pm=6`），**When** 回复该命令，**Then** 无任何效果、无文件被删。
2. **Given** 群管理员（`user_pm=3`），**When** 回复该命令，**Then** 默认**生效** ——
   错标本身就是全局的，能发现的人修复它对所有群都是净收益。
3. **Given** 运营方在控制台收紧了权限，**When** 群管理员回复该命令，**Then** 无效，仅 master 可用。
4. **Given** master（`user_pm=0`），**When** 回复该命令，**Then** 生效。
5. **Given** 任何一次成功删除，**Then** 日志记下谁、在哪个会话、删了哪个文件、影响了几条记录。

---

### Edge Cases

- **标签两侧带括号或空格**（`删除【黑丝】`）→ 与不带时等价。
- **该类型删到只剩 0 张** → 删除成功；之后抽该类型静默（与"空文件夹"表现一致）。
- **同一张图被多人、多群抽到** → 全部受影响者都能重抽。
- **删除后当天再次被抽到** → 不可能：文件已不存在，且受影响者走的是重抽路径。
- **并发**：删除与他人正在抽图同时发生 → 不得出现"记录指向已删文件"的残留。
- **被回复的是机器人发的非抽图消息**（如帮助、授权确认）→ 拒绝并说明。
- **私聊中回复删除** → 允许（图库是全局的，私聊同样能发现错标）。
- **同名文件存在于多个子目录** → 必须按**完整路径**删除，不能按 8 位短 ID 误删同名文件。
- **文件已被外部删除** → 不报错，清理记录并告知。
- **磁盘只读 / 权限不足** → 报告失败，且不得留下"记录已清但文件还在"的不一致。

## Requirements *(mandatory)*

### Functional Requirements

**识别**

- **FR-501**: 系统 MUST 能把一条「回复 + `删除<标签>`」对应到本地图库中的**唯一一个文件**，
  或者明确报告无法唯一确定。
- **FR-502**: 识别 MUST NOT 依赖适配器返回被回复的图片内容 —— 实测该字段为空。
- **FR-503**: 当无法唯一确定时，系统 MUST NOT 删除任何文件。
- **FR-504**: 标签与实际所属类型不一致时 MUST 拒绝，且不删除。
- **FR-505**: 标签参数 MUST 容忍两侧括号与空白，并与既有类型归一化一致。

**删除与重抽**

- **FR-506**: 确认后 MUST 从本地图库删除该文件。
- **FR-507**: MUST 让**当天抽到该图的所有用户**（跨群、跨会话）能够重新抽取。
- **FR-508**: 重抽 MUST 拿到与被删图片**不同**的图。
- **FR-509**: 删除后该图片 MUST NOT 再被任何人抽到。
- **FR-510**: 文件删除与记录清理 MUST NOT 出现只完成一半的持久状态。
- **FR-511**: 删除 MUST 立即生效，不得等待目录扫描缓存过期。

**权限与留痕**

- **FR-512**: 该命令默认 MUST 允许群管理员及以上（`user_pm <= 3`）。
- **FR-513**: MUST 提供配置项，可把权限**收紧**到 master / superuser（`user_pm <= 1`）。
- **FR-514**: 每次成功删除 MUST 记录操作者、会话、被删文件、受影响记录数。
- **FR-515**: 每一种失败 MUST 给出彼此不同且可操作的回复。

### Key Entities

- **已发图片回执 (SentImageRef)**：一条已发出的抽图消息与它所用文件的对应关系，用于从回复反查。
- **删除结果 (DeleteOutcome)**：被删文件、受影响的记录数、以及失败原因（如有）。
- **图片文件 / 每日记录**：沿用既有定义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-501**: 对一张刚发出的抽图回复 `删除<正确标签>`，文件从磁盘消失，且抽到它的人能立刻重抽到另一张。
- **SC-502**: 所有识别失败与标签不匹配的情形下，图库文件数**零减少**。
- **SC-503**: 删除后该图片在任何群、任何用户、任何时间都不再被抽到。
- **SC-504**: 同一张图被 N 个用户（可跨群）抽到时，N 个人**全部**能重抽。
- **SC-505**: 普通群友（`user_pm=6`）在任何配置下都无法删除任何文件。
- **SC-506**: 每次成功删除都能从日志里还原出「谁、何时、删了哪个文件」。
- **SC-507**: 四种失败（认不出、多候选、标签不符、非抽图消息）回复互不相同。

## Assumptions

- **「admin/master」默认按群管理员及以上（`pm<=3`）实现**，并提供配置可收紧到仅 master。
  理由：**错标本身就是全局的** —— 一张图被打错标签，对所有群都是错的。
  能发现它的人把它修掉，对所有群都是净收益；因此"删除影响所有群"不构成收紧权限的理由。
  另外在本部署中 `data/TodayImage/` 是从 Immich 导出的**副本**，原图仍在 Immich 里，
  重新导出即可恢复 —— "不可逆"这条顾虑也不成立。
  收紧开关保留给「图库不是导出副本、删除确实不可恢复」的部署。
- 识别依赖**发送时记录消息 ID**。核心的 `bot.send` 只有在 `wait_recall=True` 时才返回消息 ID，
  且该能力取决于适配器；因此识别能力被视为**尽力而为**，失败时退回明确报错（研究 R2/R3）。
- 「重新抽一次」复用 feature 004 已有的重置机制（清记录 + 代数 + 排除集），
  只是作用范围从「整个类型」收窄为「持有该图的那些记录」。
- 删除针对**文件**，不针对短 ID —— 短 ID 由文件名派生，可能在不同子目录下重复。
- 不提供撤销。在图库由 Immich 等外部库导出的部署中，恢复手段是重新导出；
  对于图库即原始数据的部署，运营方应打开收紧开关并自行备份。
- 不改变私聊「不限次数」的行为；私聊没有当日绑定可清理，删除文件即可。

## Out of Scope

- 把错标的图**移动**到正确类型（本功能只删除）。
- 批量删除、按标签清理。
- 撤销删除 / 回收站。
- 修改 wd14 的打标结果或 Immich 中的原图 —— 本功能只动 `data/TodayImage/` 下的副本。
