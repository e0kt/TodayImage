# TodayImage

> 基于 [早柚核心 (gsuid_core)](https://github.com/Genshin-bots/gsuid_core) 的「今日 \<类型\>」本地图库插件

![Python](https://img.shields.io/badge/python-%E2%89%A53.11-blue)
![GsCore](https://img.shields.io/badge/gsuid__core-plugin-orange)
![License](https://img.shields.io/badge/license-GPL--3.0-green)
![Tests](https://img.shields.io/badge/tests-222%20passing-brightgreen)

把图片按类型放进文件夹，插件就为每个文件夹提供一条 `今日<类型>` 命令 —— `今日黑丝`、`今日白丝`、`今日制服`。
**新建文件夹即刻可用，不需要重启核心，也不需要重载。**

**群聊**里行为对齐 TodayWaifu 的「今日萝莉」：同一个人在同一个群里、同一天内重复发送，返回的是**同一张**图，
北京时间 0 点才重新抽。**私聊不限次数**，每次都重新随机。

---

## 特性

| | |
| --- | --- |
| **动态类型** | 一级文件夹名即类型名，收到消息时才解析，加文件夹无需重启无需重载 |
| **群聊每日固定** | 群里每人 / 每群 / 每类型每天固定一张，北京时间 0 点重置（不跟随服务器时区） |
| **私聊不限次数** | 私聊每次都重新随机，不定桩、不写每日记录 |
| **同群不撞图** | 同一天同一个群里，不同的人不会抽到同一张（图不够分时才退回允许重复） |
| **分群授权** | 群里每个类型需群管理员先授权，可为不同群设置不同尺度；**私聊不受限制** |
| **不暴露图库** | 未知 / 被屏蔽 / 未授权 / 空文件夹一律静默且**互不可区分**，无法靠试探枚举服务器上有哪些类型 |
| **与 TodayWaifu 共存** | 默认屏蔽 `今日老婆`、`今日萝莉` 等命令；动态触发器**非阻断**，不会吃掉其它插件的 `今日X` |
| **零额外依赖** | 除 GsCore 本身外不引入任何第三方库 |

## 安装

必须先部署好 GsCore。把仓库放进核心的插件目录：

```bash
cd <gsuid_core>/gsuid_core/plugins
git clone https://github.com/e0kt/TodayImage.git
```

然后**重启一次** GsCore。只有首次安装需要重启。

## 快速上手

```bash
mkdir -p <gsuid_core>/data/TodayImage/黑丝
cp /some/pics/*.jpg <gsuid_core>/data/TodayImage/黑丝/
```

私聊机器人发送 `今日黑丝` 即可出图，**私聊可以一直发一直出新图**。
群里还需要群管理员先发送 `TodayImage允许黑丝`（见下方[分群授权](#分群授权)），且群里每天每类型只给一张。

## 图片目录

图片根目录默认就是 `<gsuid_core>/data/TodayImage/`，可在网页控制台改。
**根目录下的每个一级文件夹就是一个类型，文件夹名即命令后缀：**

```text
data/TodayImage/
├── 黑丝/                    → 今日黑丝
│   ├── a.jpg
│   └── 画师A/               子目录会被递归扫描
│       └── b.png
├── 白丝/                    → 今日白丝
│   └── c.jpeg
├── 制服/     ← 新建这个文件夹，就多了「今日制服」
│
├── config.json              这几个是插件自己的数据文件，
├── categories.json          是文件不是文件夹，不会被当成图片类型
├── daily_records.json
└── group_permissions.json
```

支持 `.jpg .jpeg .png .webp .gif .bmp`，其余文件和以 `.` 开头的（如 `.DS_Store`）都会被忽略。

> 不确定路径？主人发送 `查看图片` 或 `今日图片帮助`，机器人会打印当前的图片根目录与类型清单。

## 命令

### 所有人

| 命令 | 说明 |
| --- | --- |
| `今日<类型>` | 抽取当天该类型的图片，全天固定 |
| `今日图片帮助` | 查看用法；类型清单与管理命令仅主人可见 |

### 群管理员及以上

| 命令 | 说明 |
| --- | --- |
| `TodayImage允许<类型>` | 允许本群使用该类型 |
| `TodayImage禁止<类型>` | 撤销，下一条消息即生效 |
| `TodayImage列表` | 查看**本群**已允许的类型 |

### 主人 / 上传白名单

| 命令 | 权限 | 说明 |
| --- | --- | --- |
| `上传图片 <类型>` | 主人 / 白名单 | 把消息附带的图片存进该类型文件夹 |
| `查看图片 [<类型>]` | 主人 | 列出全部类型，或某类型下的图片与图片ID |
| `删除图片 <类型> [图片ID]` | 主人 | 按ID删除单张，不带ID删除该类型全部 |
| `重载图片类型` | 主人 | 立即刷新缓存（可选，新文件夹本来就会自动生效） |

## 群聊与私聊的区别

| | 群聊 | 私聊 |
| --- | --- | --- |
| 需要授权 | 需群管理员 `TodayImage允许<类型>` | **不需要** |
| 抽图次数 | 每人每天每类型固定一张 | **不限次数，每次重抽** |
| 同群不撞图 | 是 | 不适用 |
| 写入每日记录 | 是 | 否 |

## 分群授权

群聊里每个类型都需要群管理员先授权，这样一个机器人可以在不同群里用不同尺度。**私聊完全不受限制。**

```
管理员: TodayImage允许黑丝
机器人: 已允许本群使用【黑丝】。

群友:   今日黑丝
机器人: [图片]

群友:   今日白丝
机器人: (没有反应 —— 本群没开这个类型)
```

- 「群管理员及以上」= 群管理员 / 群主 / superuser / 主人（GsCore 的 `user_pm <= 3`）
- 类型名两侧的括号和空格会自动去掉，`TodayImage允许【黑丝】` 和 `TodayImage允许 黑丝` 等价
- 授权与文件夹是否存在互不相干：可以先授权再建文件夹
- **黑名单优先于授权**：就算建了个叫「老婆」的文件夹并授权，`今日老婆` 也仍然不会被本插件回复

> [!WARNING]
> **群聊默认什么都不允许。** 首次安装或升级到 v0.3 后，所有群都要由管理员逐个授权才能出图。
> 建议顺序：先想好每个群开哪些类型 → 重启 → 逐群 `TodayImage允许<类型>` → 用 `TodayImage列表` 核对。
> 想让新群默认带上一些类型，可在控制台设置「新群默认允许的类型」——
> 它只对**还没有任何授权记录**的群生效，不会把管理员撤销过的类型放回去。

## 多平台 / Discord 接入

插件不直接对接任何平台，消息由 GsCore 的适配器送进来，所以理论上适配器支持什么平台就能用什么平台。
为接入 Discord 这类**频道型**平台，插件侧做了这些准备：

### 会话类型的判定

GsCore 的 `user_type` 有四个取值：`group` / `direct` / `channel` / `sub_channel`。
Discord、KOOK、QQ 频道用的是 **`channel`（服务器频道）和 `sub_channel`（线程）**，不是 `group`。

插件统一用 `tdi/chat_context.py` 判定，规则与核心自身一致（核心判私聊一律看 `user_type != "direct"`）：

| 场景 | `user_type` | `group_id` | 判定 | 授权键 |
| --- | --- | --- | --- | --- |
| QQ 群 | `group` | `465…` | 群聊 | `465…` |
| QQ / Discord 私聊 | `direct` | — | **私聊** | — |
| Discord 服务器频道 | `channel` | `chan-123` | 群聊 | `chan-123` |
| Discord 线程 | `sub_channel` | `thread-9` | 群聊 | `thread-9` |
| 频道但适配器没填 `group_id` | `channel` | `None` | **仍算群聊** | 空键 → 拒绝 |
| 适配器忘了给私聊设 `direct` | `group` | `None` | 私聊 | — |
| 适配器自造的新取值 | `guild_forum` | 任意 | **仍算群聊** | fail closed |

倒数第三行是重点：如果按 `group_id is None` 判私聊，一个没填 `group_id` 的 Discord 频道会被当成私聊，
**分群授权会被整个绕过**。插件有测试专门钉住这一条，并禁止任何模块再用 `group_id` 做会话分类。

### 授权粒度

授权键就是 `group_id`，所以 **Discord 的每个频道、每个线程都要单独授权**。
线程不会继承父频道的授权 —— 事件里拿不到父频道 ID，与其猜，不如让它 fail closed。

### 每日记录跨平台隔离

记录键含 `bot_id`，所以 Discord 的 DM 是 `direct:discord:<uid>`、QQ 的是 `direct:onebot:<uid>`，
同一个人在两个平台上互不干扰。

### 接入时必须先验证的一件事

> [!IMPORTANT]
> **Discord 适配器是否会下发 `user_pm`？**
> 分群授权命令挂在 `pm=3` 的 SV 上，靠核心用 `user_pm` 拦人。QQ 的 OneBot 适配器会给群管理员下发 `user_pm=3`，
> 但 Discord 适配器是否把服务器管理员映射成 `pm<=3` **需要实测**。
>
> 如果它恒发 `user_pm=6`，那么 Discord 上只有机器人主人（`masters` 配置里的账号，`pm=0`）能授权频道 ——
> 功能仍可用，但管理员自助授权不可用。
>
> 验证方法：让一个 Discord 服务器管理员发一条消息，在 `data/logs/` 里查该事件的 `user_pm` 值。

### 图片体积

Discord 对普通服务器有单文件上限（约 10MB）。插件的「单张图片大小上限」默认也是 10MB，
但那只限制**上传**；已在图库里的大图发送失败与否取决于适配器与平台，必要时自行压缩图库。

## 为什么查不到的类型不给提示

发送一个不存在的类型（例如 `今日不存在`），机器人**不会有任何回复**。
未知、被屏蔽、未授权、空文件夹这四种情况在外部**完全无法区分** —— 这是刻意设计：
只要它们的回复有差别，任何人都能靠逐个试探把服务器上有哪些类型问出来。

排查请看 `<gsuid_core>/data/logs/`，每次静默都有 `debug` 日志说明原因（`unknown` / `blocked` / `unauthorised` / `empty`）。
管理员也可以用 `TodayImage列表` 查看本群的授权情况。

## 配置

全部配置都在 GsCore 网页控制台，存放于 `data/TodayImage/config.json`，插件升级不会丢失。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用今日图片 | 开 | 总开关 |
| 图片根目录 | 空 | 留空即 `data/TodayImage` 本身。改后需重启 |
| 命令前缀 | `今日` | 留空会退回 `今日`。改后需重启 |
| 抽图文案模板 | `你今天的{类型}来啦！` | 可用 `{类型}` 变量 |
| 群聊中艾特发送者 | 开 | 私聊始终不艾特 |
| 私聊不限次数 | 开 | 私聊每次重抽、不写每日记录；关闭则私聊也变成每天一张。群聊始终固定，不受此项影响 |
| 同群同类型不重复 | 开 | 图不够分时自动退回允许重复 |
| 每日重置时区(UTC偏移小时) | `8` | 按北京时间 0 点重置，不跟随服务器时区 |
| 新群默认允许的类型 | 空 | 只对没有授权记录的群生效 |
| 不回复的命令 | 已含 TodayWaifu 今日系列 | 按前缀匹配，填写内容与默认名单合并 |
| 图片列表转发阈值 | `10` | 超过则用合并转发 |
| 图片上传白名单 | 空 | 主人无需加入 |
| 单张图片大小上限(MB) | `10` | 超限的上传计入失败 |
| 目录扫描缓存时间(秒) | `300` | 也决定新文件夹多久自动生效；`0` 表示每次都扫 |

每个类型的单独设置（启用 / 别名 / 文案）在 `data/TodayImage/categories.json`：

```json
{
  "version": 1,
  "categories": {
    "黑丝": { "enabled": true, "aliases": ["丝袜"], "caption": "今天的黑丝，请收好~" },
    "白丝": { "enabled": false, "aliases": [], "caption": null }
  }
}
```

改完发送 `重载图片类型` 立即生效。

## 与 TodayWaifu 共存

两个插件可以同时安装。TodayWaifu 的 `今日老婆`、`今日萝莉`、`今日战双老婆` 等命令都在默认屏蔽名单里，
本插件一律不回复 —— 即使真的建了一个叫 `老婆` 的文件夹也不会抢答。

反过来，本插件的动态触发器是**非阻断**的，不会吃掉任何其它插件的 `今日X` 命令。
测试里有一条会实际枚举 TodayWaifu 注册的所有 `今日*` 触发器并逐个断言在屏蔽名单内，
所以上游新增命令而这边忘了屏蔽时，测试会先红。

## 开发

插件在仓库内开发，**测试不需要安装 GsCore**：

```bash
git clone https://github.com/e0kt/TodayImage.git
cd TodayImage
python -m unittest discover -s tests -v
```

核心逻辑（图库扫描、类型解析、每日记录、分群授权、黑名单、图片解码、缓存）全是只依赖标准库的纯模块，
测试通过 `importlib` 直接加载文件，因此无核心、无机器人也能跑。

装进 GsCore 后再跑一次，会额外执行框架契约测试（`sv.TL` 形状、`pm=3` 权限闸门、TodayWaifu 命令屏蔽覆盖率）：

```bash
PYTHONPATH=<gsuid_core>:<gsuid_core>/gsuid_core \
  <gsuid_core>/.venv/bin/python -m unittest discover -s tests
```

设计文档在 `specs/`，用 [spec-kit](https://github.com/github/spec-kit) 分三轮迭代写成，
每一轮都有 spec / research / plan / tasks，记录了做过的取舍和被否决的方案。
