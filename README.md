# TodayImage

基于 [早柚核心 (gsuid_core)](https://github.com/Genshin-bots/gsuid_core) 的「今日图片」插件。

把图片按类型放进文件夹，插件就为每个文件夹提供一条 `今日<类型>` 命令 —— `今日黑丝`、`今日白丝`、`今日制服`。
同一个人在同一个群里、同一天内重复发送，返回的是**同一张**图；**北京时间 0 点**才会重新抽。
同一天同一个群里，不同的人也不会抽到同一张图（图片数少于人数时才会退回允许重复）。
行为对齐 TodayWaifu 的「今日萝莉」。

## 安装

本插件必须先部署好 GsCore 才能使用。把仓库放到核心的插件目录下即可：

```bash
ln -s /path/to/TodayImage /path/to/gsuid_core/gsuid_core/plugins/TodayImage
```

然后重启一次 GsCore。**只有首次安装需要重启**，之后新增图片类型用 `重载图片类型` 即可生效。

## 快速上手

```bash
mkdir -p gsuid_core/data/TodayImage/黑丝
cp /some/pics/*.jpg gsuid_core/data/TodayImage/黑丝/
```

在聊天里发送 `重载图片类型`，然后发送 `今日黑丝`。

## 图片目录

### 👉 想加新类型，就在这里建文件夹

```text
gsuid_core/data/TodayImage/          ← 图片根目录（可在控制台改）
├── 黑丝/                            → 今日黑丝
│   ├── a.jpg
│   └── 画师A/                       子目录会被递归扫描
│       └── b.png
├── 白丝/                            → 今日白丝
│   └── c.jpeg
├── 制服/          ← 新建这个文件夹，就多了「今日制服」
│   └── d.png
│
├── config.json          这三个是插件自己的数据文件，
├── categories.json      不是文件夹，不会被当成图片类型
└── daily_records.json
```

**一级文件夹名 = 类型名 = 命令后缀。** 建完文件夹放好图就能用 —— 类型是收到消息时才解析的，
**不需要重启，也不需要重载**（缓存过期后自动生效，想立刻生效可发送 `重载图片类型`）。

支持 `.jpg .jpeg .png .webp .gif .bmp`，其余文件、以及 `.` 开头的文件/文件夹（如 `.DS_Store`）都会被忽略。

不确定路径？主人发送 `查看图片` 或 `今日图片帮助`，机器人会打印当前的图片根目录与类型清单。

> **注意**：普通用户看不到类型清单。发送一个不存在的类型（例如 `今日不存在`）机器人**不会有任何回复** ——
> 未知、被屏蔽、空文件夹在外部完全无法区分，这是刻意设计，避免有人靠试探把本机的文件夹名问出来。
> 排查请看 `gsuid_core/data/logs/`，每次静默都有 `debug` 日志说明原因。

## 命令

| 命令 | 权限 | 说明 |
| --- | --- | --- |
| `今日<类型>` | 所有人 | 抽取当天该类型的图片，全天固定 |
| `今日图片帮助` | 所有人 | 查看用法；类型清单与管理命令仅主人可见 |
| `上传图片 <类型>` | 主人 / 白名单 | 把消息附带的图片存进该类型文件夹 |
| `查看图片 [<类型>]` | 主人 | 不带类型列出全部类型；带类型列出图片与图片ID |
| `删除图片 <类型> [图片ID]` | 主人 | 按ID删除单张，不带ID删除该类型全部 |
| `重载图片类型` | 主人 | 重新扫描目录并刷新命令，无需重启核心 |

## 配置

全部配置都在 GsCore 网页控制台里，存放于 `gsuid_core/data/TodayImage/config.json`，插件升级不会丢失。
每个类型的单独设置（启用/别名/文案）在 `gsuid_core/data/TodayImage/categories.json`：

```json
{
  "version": 1,
  "categories": {
    "黑丝": { "enabled": true, "aliases": ["丝袜"], "caption": "今天的黑丝，请收好~" },
    "白丝": { "enabled": false, "aliases": [], "caption": null }
  }
}
```

改完发送 `重载图片类型` 生效。

### 控制台配置项

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用今日图片 | 开 | 总开关，关闭后所有命令都不响应 |
| 图片根目录 | 空 | 留空即 `data/TodayImage` 本身。改后需重载 |
| 命令前缀 | `今日` | 留空会退回 `今日`。改后需重载 |
| 抽图文案模板 | `你今天的{类型}来啦！` | 可用 `{类型}` 变量 |
| 同群同类型不重复 | 开 | 同一天同群同类型，两个人不会抽到同一张图；图不够分时自动退回允许重复 |
| 每日重置时区(UTC偏移小时) | `8` | 按北京时间 0 点重置，不跟随服务器时区 |
| 新群默认允许的类型 | 空 | 只对**没有任何授权记录**的群生效，不会把管理员撤销过的类型放回去 |
| 不回复的命令 | 已含 TodayWaifu 今日系列 | 这些命令一律不回复，即使存在同名文件夹。按前缀匹配，填写内容与默认名单合并 |
| 群聊中艾特发送者 | 开 | 私聊始终不艾特 |
| 图片列表转发阈值 | 10 | 超过则用合并转发 |
| 图片上传白名单 | 空 | 主人无需加入 |
| 单张图片大小上限(MB) | 10 | 超限的上传计入失败 |
| 目录扫描缓存时间(秒) | 300 | 0 表示每次都重新扫描 |

## 分群授权（重要：升级后群里会先失效）

从这个版本起，**群聊里的每个类型都需要群管理员先授权**，私聊不受影响。

> [!WARNING]
> 升级重启后，**所有群都会先变成「什么都发不了」**，直到管理员逐个授权。这是刻意的安全默认值。
> 建议顺序：先想好每个群开哪些类型 → 重启 → 在每个群里逐条 `TodayImage允许<类型>` → 用 `TodayImage列表` 核对。

| 命令 | 权限 | 说明 |
| --- | --- | --- |
| `TodayImage允许<类型>` | 群管理员及以上 | 允许本群使用该类型 |
| `TodayImage禁止<类型>` | 群管理员及以上 | 撤销，下一条消息即生效 |
| `TodayImage列表` | 群管理员及以上 | 查看**本群**已允许的类型 |

「群管理员及以上」= 群管理员 / 群主 / superuser / 主人（GsCore 的 `user_pm <= 3`）。
类型名两侧的括号和空格会被自动去掉，`TodayImage允许【黑丝】` 和 `TodayImage允许 黑丝` 等价。

**私聊完全不受限制**，不需要任何授权，行为和之前一致。

如果想让**新加入的群**默认带上一些类型，可在控制台设置「新群默认允许的类型」——
它只对还没有任何授权记录的群生效，不会把管理员撤销过的类型放回去。

## 与 TodayWaifu 共存

两个插件可以同时安装。命令、配置与数据完全独立（本插件只写 `data/TodayImage/`）。
TodayWaifu 的 `今日老婆`、`今日萝莉`、`今日战双老婆` 等命令已在默认屏蔽名单里，本插件一律不回复 ——
即使你真的建了一个叫 `老婆` 的文件夹也不会抢答。反过来，本插件的动态触发器是**非阻断**的，
不会吃掉任何其它插件的 `今日X` 命令。

## 开发

插件在本仓库内开发，测试不需要安装 GsCore：

```bash
python -m unittest discover -s tests -v
```

核心逻辑（图库扫描、类型解析、每日记录、图片解码、缓存）都是只依赖标准库的纯模块，
测试通过 `importlib` 直接加载文件，因此无核心、无机器人也能跑。
